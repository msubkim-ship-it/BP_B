## Keep — 유지할 것

> 교육·프로젝트 과정에서 **효과적이었던** 프롬프팅, 습관, 협업 방식을 적습니다.

1. Session Report와 Transcript를 함께 관리하여, 세션별 프롬프트와 결과를 나중에 추적하기 쉬웠습니다.
2. RED는 `pytest.fail`, GREEN은 최소 구현, REFACTOR는 Golden Master 기반으로 진행하는 단계별 게이트가 전반적으로 잘 지켜졌습니다.

---

## Problem — 문제점

> **막혔던 점**, AI 활용의 어려움, 오해, 불편, 아쉬움을 솔직히 적습니다. (비난이 아닌 성찰)

1. 개인적으로 Mom Test와 페르소나 활용 방법이 익숙하지 않아 실제 프롬프트에 충분히 반영하지 못했습니다.
2. Base branch를 main, red, green, staging 중에서 혼동하는 사례가 있었고, 한 PR에 여러 Phase 커밋이 함께 포함되어 리뷰 범위가 모호해지는 경우가 있었습니다.
3. PR 본문이 비어 있는 경우 핵심 맥락이 Report에만 남아 있어, 리뷰어가 코드 diff와 Prompting·Report를 각각 확인해야 전체 흐름을 이해할 수 있었습니다.

## Try — 시도할 것

> 다음 프로젝트·학습에서 **바꿔볼 구체적 행동**을 적습니다.

1. PR 생성 시 base branch를 재확인하고, RED/GREEN/REFACTOR → staging 머지 규칙을 체크리스트로 관리해 보겠습니다.
2. PR 본문에 목적, 범위, 관련 Report 링크를 포함하는 간단한 템플릿을 적용하면 좋겠습니다.
3. 현업 VS Code 환경에서 Cursor Rule·Skill·Command에 해당하는 워크플로를 어떤 Tool 조합으로 대체할 수 있을지 검토해 보겠습니다.
