## Keep — 유지할 것

> 교육·프로젝트 과정에서 **효과적이었던** 프롬프팅, 습관, 협업 방식을 적습니다.

1. **ARRR 단계를 나눠 요청했다.** `@arr-phase/SKILL.md`와 함께 「RED만」「green만」「refactoring만」처럼 Phase를 먼저 선언하니, AI가 구현·테스트·리팩토링을 한꺼번에 섞지 않고 답변이 훨씬 집중됐다. 특히 RED에서 「구현 금지, pytest.fail만」이라고 제약을 명시한 뒤에는 불필요한 코드 생성이 거의 없었다.

2. **반복 규약은 Rule로 고정했다.** venv에서만 pytest를 돌리겠다는 요구를 매번 채팅에 쓰지 않고 `.cursor/rules/python-env.mdc`로 옮겼더니, 이후 단계에서 AI가 알아서 가상환경 경로를 썼다. 「자주 쓰는 전제」는 프롬프트가 아니라 Rule로 두는 편이 낫다는 걸 배웠다.

3. **Report와 Transcript를 짝으로 남겼다.** 단계가 끝날 때마다 `Report/{phase}-report.md`와 Export Transcript를 맞춰 두니, 다음 채팅에서 「이전에 뭘 했는지」를 다시 설명하지 않아도 됐다. AI에게 `@Report/refactoring-report.md`만 넘겨도 맥락이 이어졌다.

4. **팀 리뷰 내용을 AI에게 구조화 요청했다.** 「PR #3·#4 리뷰 중 refactoring에 넣을 것만 적용해줘」「어떤 코멘트를 참고했는지 URL까지 Report에 써줘」처럼 범위를 좁혀 요청하니, 내가 리뷰 스레드를 일일이 정리하지 않아도 추적 가능한 산출물이 나왔다.

## Problem — 문제점

> **막혔던 점**, AI 활용의 어려움, 오해, 불편, 아쉬움을 솔직히 적습니다. (비난이 아닌 성찰)

1. **한 번에 너무 많은 맥락을 넣으면 답이 산만해졌다.** 초반에는 Dual-Track 표·PRD·venv·GitHub 반영을 한 메시지에 담은 적이 있는데, AI 답변은 길어지고 내가 검토할 포인트를 놓치기 쉬웠다. 나중에 Phase·Track 단위로 쪼개니 훨씬 관리하기 쉬웠다.

2. **AI 제안을 충분히 이해하기 전에 넘어간 순간이 있었다.** green 단계에서 테스트용 레지스트리를 코드에 직접 박아 두는 방식이 나왔을 때, 당장 테스트가 통과해서 그대로 두었다가 팀 리뷰에서 「`units.json`과 SSOT를 맞추자」는 피드백이 왔다. AI가 빠르게 만든 초안을 내가 구조까지 검증하지 않은 게 아쉬웠다.

3. **출력 형식처럼 「정답이 문서에 여러 개」인 주제는 AI만으로는 정리가 안 됐다.** README 한 줄형과 부록 table 4자리가 달라서, AI에게 SSOT를 물어도 혼선이 있었고 결국 팀 리뷰·사용자 확인으로 table 기본을 확정했다. 모호한 요구는 AI에게 맡기기 전에 내가 먼저 한 줄로 결정할 기준을 적어야 했다.

4. **Mom Test와 PRD 단위 범위가 달라서 혼란스러웠다.** Pain은 inch/cm인데 실습 단위는 meter/feet/yard라, AI에게 회고·KPI를 쓸 때도 스코프 설명이 길어졌다. 사용자 관점(Pain)과 제품 SSOT(PRD)를 프롬프트에 같이 쓸 때 「어느 쪽이 기준인지」를 먼저 밝히지 않으면 AI 답이 흔들렸다.

## Try — 시도할 것

> 다음 프로젝트·학습에서 **바꿔볼 구체적 행동**을 적습니다.

1. **요청은 항상 「한 Phase + 한 Track + 완료 조건」으로 쪼개겠다.** 예: 「red 브랜치, Track B만, 6건 pytest.fail, skip 금지, 끝나면 pytest 결과만 보여줘」처럼 DoD를 프롬프트 맨 위에 적겠다.

2. **AI가 코드를 제안하면 먼저 「왜 이 구조인지」만 답하게 하고, 내가 이해한 뒤 적용하겠다.** 특히 테스트 fixture·설정 파일·예외 계층처럼 나중에 리팩토링 비용이 큰 부분은 green 직후 5분이라도 구조 질문을 넣겠다.

3. **팀 리뷰 전에 프롬프트 초안을 페어에게 공유하겠다.** 「이번 단계 AI에게 뭘 맡기고, 내가 뭘 검증할지」를 짧게 맞춘 뒤 실행하면, 리뷰에서 되돌리는 시간을 줄일 수 있을 것 같다.

4. **단계 마감 DoD에 Transcript Export를 넣겠다.** Report만 있고 대화 원본이 없으면 나중에 「그때 왜 이렇게 요청했지?」가 기억나지 않았다. 다음부터는 merge 전 `Prompting/{phase}-transcript.md` 저장을 체크리스트에 포함하겠다.
